# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Generates interactive PDF workbooks (AcroForm fields, A4) with ReportLab for "Marge de Manœuvre" (MDM), a French career-coaching / bilan de compétences practice. All user-facing content (PDF text, LLM prompts, UI, docs) is in French and should stay French. `Agent.md` and `SKILL.md` at the repo root are the original (French) design rules and workflows; read them before larger changes.

## Commands

Always run from the repository root: asset paths resolve from `PDFStyle.PROJECT_DIR`, and the PDF output path is relative to the cwd. The virtualenv lives in the main checkout (`.venv`, Python 3.14); from a worktree under `.claude/worktrees/<name>/` it is `../../../.venv`.

```bash
python Scripts/main_generate_chap1.py --output chap1.pdf
pip install -r requirements-dev.txt
python -m pytest tests
python -m pytest tests/test_pdf_compiler.py -k field_names
python Scripts/test_all_templates.py
python -m uvicorn server.app:app --port 8080 --reload
```

- Every `Scripts/main_generate_*.py` (`carnet_1`, `carnet_2`, then the former chap0–chap6 until the clean-up PR, `livret`, `business_plan`, `programme`) takes `--output`. Exit code 0 plus `PDF generated successfully: ...` means it built.
- `tests/` is the pytest suite (compiler, reference workbooks and API; Gemini is faked by monkeypatching `gemini_service.genai.Client`). It needs `requirements-dev.txt` (pytest, pymupdf, httpx). There is no linter config.
- CI (`.github/workflows/tests.yml`, on pull requests and pushes to `main`) runs pytest and builds every CLI document (each `Scripts/main_generate_*.py`) on Python 3.14.
- Python 3.14 everywhere (local `.venv`, `python:3.14-slim` in Docker, CI). `requirements.txt` and `requirements-dev.txt` are lock files with every package pinned, for Windows and Linux alike. Edit the direct dependencies in `requirements.in` / `requirements-dev.in`, then regenerate both locks with the `uv pip compile ...` commands written at the top of each (`pip install uv` first), `requirements.txt` first since the dev lock is constrained by it.
- `Scripts/test_*.py` are not tests but showcase scripts that render `Test_*.pdf` at the repo root. `test_composite_page.py` also writes PNG previews to `previews/` (git-ignored).
- If `DocumentBuilder` raises `PermissionError: Cannot overwrite ...`, the target PDF is open in another program.
- Generated PDFs are git-ignored. `scratch/` holds committed page PNG previews.
- Deployment (Cloud Run via `Dockerfile`; `GEMINI_API_KEY` is injected from the Secret Manager secret `gemini-api-key`, never set as a plain env var) is covered in `server/DEPLOY_CLOUD_RUN.md`.

## Architecture

One rendering library and one engine (`workbook_generator.compiler`) serve both entry points, the CLI and the web app, from one content source: the JSON files of `workbooks/`.

### 1. Rendering library: `Scripts/workbook_generator/`
- The art direction is « Éditorial & Affirmé » (`DA-workbook.md`, `design-system/`): warm ivory pages (`PDFStyle.COLOR_PAGE` #FFF8EC, chosen by the user over the DA cream and linen, painted under each page by the canvas `DocumentBuilder` creates, so page functions never draw a background), an eyebrow or pill label then a punctuated title whose last word (or `*marked words*`) is coral, pastel cards, white answer boxes bordered in `line-strong`, PT Mono folio. One palette only.
- Tone (DA section 7): vouvoiement, short affirmative sentences, punctuated sentence-case titles; never « coach » (say « consultant en transformation » or « la personne qui vous accompagne »), no personal-development wording (« quête de sens », « croyances limitantes », « syndrome de l'imposteur »…), never « présentiel », no unsourced figure. The Gemini prompts share these rules (`TONE_RULES` in `gemini_service.py`).
- `DocumentBuilder(output_path, pastel=None, folio="", carnet=None)` is the entry point for every document. It registers fonts from `assets/fonts` (falls back to Helvetica, Courier, Times) and wraps the canvas. `carnet=N` (1–7, or `"route"` for the carnet de route) sets the dominant pastel (`PDFStyle.CARNET_PASTELS`, by stage of the programme: sky, lilac, mint, sky, lilac, then almond, blush, then jasmine), the folio « carnet N/7 » or « carnet de route », and the cover and opener eyebrow (`carnet_eyebrow`: « Carnet de bord · carnet N » or « Carnet de route »); other documents pass a short `folio` and a `pastel`. These per-document settings live on the canvas (`document_style(c)`, `document_pastel(c)`), not on `PDFStyle`. The PDF catalog declares the language (`PDFStyle.PDF_LANG`, fr-FR). `output_path` can be a file path or a `BytesIO`. `add_page(fn, *args)` just calls `fn(canvas, *args)`.
- **Each page function must end its own page.** `PageLayout.render()` and the `create_standard_*` / `create_closing_page` helpers call `c.showPage()`. Hand-drawn pages must call it themselves. `add_page` does not.
- `config.PDFStyle` holds the tokens: colors (`COLOR_INK`, `COLOR_CORAL_STRONG`, `PASTELS`…), the print type scale (`SIZE_*`), layout values. `register_fonts()` overwrites the `FONT_*` attributes (fallbacks), so read `PDFStyle.X` at draw time and never hard-code hex colors.
- `templates.PageLayout` is a vertical flow layout. You add blocks (`add_text`, `add_questions_group` for auto-sized question boxes, plus the atomic `add_callout`, `add_cards_grid`, `add_scale_gauge`, `add_checklist`, `add_table`, `add_stat_boxes`, `add_question_block`), then call `render()`. Prefer it over manual x/y math. The house style is 2–3 blocks per page with lots of white space.
- The chapter pages also use its reading and form blocks: `add_heading`, `add_paragraphs` (items starting with « • » become a star list), `add_star_list`, `add_annotation` (the page's one handmade touch), `add_frise`, `add_info_cards`, `add_link_card` (clickable resources), `add_fields_card` (labelled boxes in rows: experience, job or contact sheets), `add_numbered_lines`, `add_rating_grid` (one radio scale per row), `add_checklist_cards`, `add_fill_in_card` (sentences with inline boxes), the drawn `add_life_line` and `add_tree_of_life` (in `drawn_blocks.py`, they fill the rest of the page), and `page_break()` to split an exercise evenly. The common template of the carnets adds `add_energy_check` (the weather of the day, 0 to 10), `add_protocol` and `add_anchor` (before and after a heavy exercise, Pennebaker's protocol) and `add_contrast_example` (« En surface » / « Exploitable »); their fixed texts are constants of `templates.py`, so customization never touches them. The reference workbooks use them as spec blocks; Gemini never creates them (it only adapts their text, see `REFERENCE_BLOCKS_RULES`).
- Nothing may run off the page. Each `add_*` calls `_ensure_space(height)`, which starts a continuation page titled `"<title> (suite)"` (and repeats table headers). `add_questions_group` packs questions page by page. The hand-drawn templates (`two_columns`, `enquete`, `roadmap`, `quadrants`) paginate the same way through their `_draw_*_page` helpers, which return the items left over. For single-line labels in fixed boxes, use `draw_fitted_text()` (shrinks, wraps, then a visible `…`).
- `primitives.py` holds the art direction's building blocks: `draw_text` (tracking, always reset: PDF `Tc` leaks into later text otherwise), `draw_paragraph`, `draw_heading` (accent title), `draw_eyebrow`, `draw_label_pill`, `draw_number`, cards, `draw_field_box`, `postit()` (a context manager), `draw_drawn_arrow`, `draw_star_list`, `draw_stamp`, `draw_icon` / `draw_icon_badge` (Material Symbols Outlined by name), `draw_frise`, `draw_logotype`, `draw_signature`, `draw_folio`, `draw_page_head`, and `draw_cover_illustration`.
- The cover illustration (the work table seen from above) is `assets/illustrations/couverture.svg`, drawn as vectors by svglib on every `create_cover_page`. Its lilac `#E7E0FF` is a placeholder that `draw_cover_illustration` swaps for the document pastel, so do not use lilac for anything else in it. svglib reads shapes, paths, transforms and opacities: no text, gradients, filters or masks. The SVG is in points (`width="595.28pt"`): unitless sizes would be read as pixels and shrunk to 75 %.
- The fonts have no emoji, ✓, ☀, ◀…: ReportLab drops them silently. Draw pictograms as icons (`draw_icon`) or vectors (stars, arrows). `compiler` cleans spec text with `utils.strip_unsupported_glyphs` (characters missing from Manrope, DM Sans or PT Mono). No font has the narrow no-break space U+202F: use U+00A0.
- French typography is automatic: every text primitive (and the summary intro, table cells) goes through `utils.french_typography` (no-break space before `: ; ! ?`, inside « », between a number and its unit; "…" → « … »; oe → œ in cœur, œuvre…), which leaves markup tags, entities and URLs alone. Line wrapping never breaks at U+00A0: split words with `utils.split_words` / `cached_simpleSplit`, never `str.split()`.
- Single-choice scales are radio groups: reserve the group name once with `forms.reserve_field_name()`, then call `forms.create_radio()` per value.
- `components.py` holds the full-page templates (`create_cover_page`, the carnet opener `create_standard_summary_page`, `_meteo_page`, `_quadrants_page`, `_two_columns_page`, `_enquete_page`, `_roadmap_page`, the end of workbook `create_standard_engagement_page` with the deliverable post-it and stamp, the blue back cover `create_closing_page`) and shared blocks (`draw_question`, `draw_answer_box`, `draw_choice_scale`). `forms.py` holds the AcroForm field helpers: `framed=False` gives a transparent field to lay over a drawn box; fields ignore canvas transforms, so never put one inside a rotated post-it. Public API is re-exported from `workbook_generator/__init__.py`.
- Performance helpers in `utils.py` (see `.jules/bolt.md`): `useA85 = 0`, `cached_simpleSplit`, `cached_image_reader` (snake_case; there is also an alias `cached_ImageReader`). Cache anything heavy drawn on every page as a Form XObject (`beginForm` / `doForm`).
- AcroForm field names must be unique across the whole PDF, since a reused id links the fields. `forms.create_input_field` / `create_checkbox` enforce this by suffixing repeats (`_2`, `_3`…), so always go through them rather than `form.textfield` directly.

### 2. The workbook format and its engine: `spec.py`, `compiler.py`, `workbooks/`
- `spec.py` holds the declarative format (`WorkbookSpec` → `PageSpec` → `BlockSpec`) and `load_workbook(id)`. A page is a template (`cover`, `summary`, `recap`, `questions`, `meteo`, `quadrants`, `two_columns`, `enquete`, `roadmap`, `engagement`, `closing`) with `params` named like the component's arguments, or a `composite` page whose `blocks` are `PageLayout.add_*` calls: lengths in cm (`*_cm`), colors by name (`"sky"`, `"coral_strong"`), tuples as lists (the `BlockSpec` docstring lists each shape). An empty `part_title` means no eyebrow; a missing one gets « N. TITRE ». The head of a file sets `carnet` (1–7 or `"route"`) or `folio` and `pastel`, and `pdf_title`.
- Pages and blocks may carry `"fixed": true` (customization never changes them; always the case for the blocks of `FIXED_BLOCK_TYPES`: protocol, anchor, energy, report) and a `data_id` (`c4.seuils`, `route.pistes`: the carnet, then a name; the list is in the map, section 7) naming the data written there. A `report` block copies such data from another carnet: each line is `[label, data_id, field_id, height_cm]`, and `compile_workbook_from_spec` prints its origin, « carnet 4 · p. 12 », with the page read from the carnet's file in `workbooks/` (`reference_data_pages`, cached until the file changes; « carnet 4 » alone when there is no file). `tests/test_workbooks.py` checks that data ids are unique, name their carnet, and that every report points to declared data.
- `workbooks/<id>.json` is the content of the carnets, the `livret` and the `business-plan`: the only copy, read by the CLI and by the app. The carnets are being restructured (`audit-carnets-2026-10/feuille-de-route-restructuration.md`): `carnet-1.json` … `carnet-7.json` and `carnet-de-route.json` arrive one PR at a time, and the former `chap0`…`chap6` (pinned to their old pastel and folio) stay until the clean-up PR. Edit text there. Files keep only what they set (no nulls, no defaults: `tests/test_workbooks.py` checks it, and that every `field_id` is unique). They were recorded from the former Python chapters and compile to the same PDFs.
- A long document lists its `parts` (titles) and each of its pages names its `part` (1, 2…): the app customizes it one part at a time, since a whole livret in one answer is too much for the model. The pages of a part follow one another (`tests/test_workbooks.py` checks it); pages outside the parts (cover, opener, back cover) are never customized part by part. The `business-plan` (the full livret for business creation, autonomous: its references to the carnets are fixed callouts « Si vous avez fait le bilan », not `report` blocks) is the first one.
- `compiler.compile_workbook_from_spec(spec, output_path=None)` returns PDF bytes, or writes to a path or a `BytesIO`. `build_reference_workbook(id, output)` compiles a file of `workbooks/`. Each `Scripts/main_generate_<id>.py` is a thin wrapper around it (the function names are kept for the tests and CI).
- Each carnet follows the common template (`audit-carnets-2026-10/carte-parcours-unifie.md`, section 4): `cover` with its promise; an opener (`summary`: title, objective, « Exercice N · nom · durée » list, `duration` and `split`; in a carnet, the frame and how-to lines are added); the weather of the day (`energy` block) and, from carnet 2, a guided recap; exercise pages whose eyebrow is « Exercice N · nom · durée », with a `contrast_example` from a neighbouring trade and, on heavy exercises, `protocol` before and `anchor` after; then `engagement` with the carnet's deliverable, the commitments and three guided zones (`pistes: true` adds the thread of leads, carnets 2 to 5) before the `closing` back cover. Exercise text keeps the vouvoiement and the tone rules above, with no gendered wording.
- Conventions for Python page functions (programme, hand-drawn components): named `create_<page>_page(c)`, the canvas is always `c` as the first argument, and the running vertical cursor is `y_pos`.

### 3. The programme brochure: `chapters/programme/`
- `chapters/programme/` (the Qualiopi programme/pricing brochure, published on the website) is built on `PageLayout` with its own self-sizing blocks in `programme/common.py` (`programme_layout`, `add_card` / `add_card_row` taking paragraph markup and star items, `add_temps_band`, `add_session_card`, `add_deliverables`, `add_bars`). Its text is regulatory (Qualiopi indicators, prices, legal references): change it only on request. Page order is set in `main_generate_programme.py`; the `create_programme_page_N` aliases in `programme/__init__.py` follow it. After building, `main_generate_programme.py` also copies the PDF into a sibling `../marge-de-manoeuvre/public/documents/` repo if that folder exists.

### 4. Web app: `server/` (FastAPI + Gemini)
- Flow: raw coaching notes → `gemini_service.parse_notes_with_gemini` → a `WorkbookSpec` (pages, each with a `template` + `params`, or `composite` + `blocks`) → `compiler.compile_workbook_from_spec` → PDF bytes. `models.py` re-exports the spec models and adds the API requests.
- Gemini calls go through `_generate_json`, which tries each model of `GEMINI_MODELS` (env var, comma-separated, default `gemini-3.8-flash` alone) on a client cached per API key (read from `GEMINI_API_KEY` only: requests cannot bring their own key), with a `GEMINI_TIMEOUT_S` timeout (default 120 s; a parse takes ~30 s). The three service functions return a `GenerationResult(value, fallback_reason)`: when there is no `GEMINI_API_KEY` (`no_api_key`) or every model fails (`model_error`), the value comes from a heuristic mock. `app.py` exposes this as `X-MDM-Generation: ai|fallback` and `X-MDM-Fallback-Reason` headers, which the UI shows as a warning banner.
- Endpoints in `app.py`: `/api/parse`, `/api/iterate` (refine a spec from feedback), `/api/customize` (adapt a predefined workbook to a beneficiary), `/api/templates[/{id}]`, `/api/compile`, `/api/quick-generate`. The UI is a single file, `server/templates/index.html`, in the DA: Tailwind (CDN) whose color families are remapped onto the DA tokens in its `tailwind.config`, the DA Google Fonts, Material Symbols icons (no emoji). `.env` at the root or in `server/` is auto-loaded.
- In production the service sits behind IAP (Cloud Run `iap-enabled`, access limited to `domain:margedemanoeuvre.fr`); the app itself has no authentication. There is no CORS middleware: the UI is same-origin.
- Input sizes are bounded by the `MAX_*` constants in `spec.py` and `models.py` (text lengths, pages, blocks per page, list items and text length anywhere in a spec, scale span). Beyond them the API answers 422, and `app.py` turns validation errors into a French string `detail` that the UI shows as is. A 500 never carries the exception text (it is logged instead).
- `compiler.py` maps each template name to a `workbook_generator` function and is deliberately lenient with param aliases (e.g. `points`/`steps`/`items`), because the specs come from an LLM. Keep that tolerance. It is also the trust boundary: spec text that reaches ReportLab paragraph markup (the summary intro) must be escaped there, and default field ids are prefixed with the page index (`p{page_idx}_…`). Only `<b>`, `<i>` and `<br/>` survive in the summary intro.
- `predefined_workbooks.py` is the app's catalogue of `workbooks/` (title, description, icon, category): the specs themselves are the JSON files, so a content edit reaches the PDF and the app at once. A new file of `workbooks/` needs a `CATALOGUE` entry (a test checks it).
- `/api/customize` sends the spec with a `_ref` on each page and block (`spec.tag_refs`), then `spec.keep_fixed` puts back everything fixed as it was (matched by `_ref`, or by position), with the carnet's identity, its parts and its data ids; an answer that lost both is refused (model error, so the fallback). With a `part`, Gemini only gets the pages of that part (`spec.part_of`) and `spec.put_part_back` puts the customized pages back in place, the rest of the document unchanged; the UI chains the calls, one part after the other, when the chosen workbook has parts (`TemplateInfo.parts`). `/api/iterate` only states the rule in its prompt: the consultant may ask to change a fixed page.
- Spec endpoints answer with `response_model_exclude_unset=True`, and the prompts get the spec through `_spec_json` (set fields only): a JSON exported from the UI is as clean as the files of `workbooks/` and can join that folder as is. Gemini may only create the 8 base blocks; `REFERENCE_BLOCKS_RULES` (in the iterate and customize prompts) tells it to keep the other blocks, their keys and their ids.

### Adding a new page template or atomic block
These pieces must stay in sync:
1. The function in `components.py` (or a `PageLayout.add_*` method in `templates.py`).
2. The export in `workbook_generator/__init__.py`.
3. The `Literal` in `PageSpec.template` or `BlockSpec.type` (and any new field) in `Scripts/workbook_generator/spec.py`.
4. The dispatch branch in `Scripts/workbook_generator/compiler.py`, and an entry in `BLOCKS` of `tests/test_workbooks.py`.
5. In `server/gemini_service.py`: the documentation inside `SYSTEM_PROMPT` if Gemini may create it, otherwise its name in `REFERENCE_BLOCKS_RULES`. A block that must never be customized also goes into `FIXED_BLOCK_TYPES` (`spec.py`, and its copy in `index.html`).
6. Its preview in `server/templates/index.html` (`referenceBlockHtml` for a block).
7. A showcase page in `Scripts/test_all_templates.py`.

## Guardrails from `Agent.md`
- Do not overwrite or delete anything in `assets/` without user confirmation.
- Reuse `components.py` / `templates.py` helpers rather than drawing directly on the canvas.
